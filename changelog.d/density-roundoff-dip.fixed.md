A density path that touches zero no longer has its translation refused when its fitted table dips below zero by rounding: a curve meeting a zero end with zero slope, or an unresolved interval ringing about a vacuum, left the table about 1e-18 of its scale below zero, and the domain check refused the run. `profile_table` now lifts each dipping interval by its dip when every dip is within 64 ulp of the table's largest value. It does so for every scalar path it tabulates, not only densities: a pre-ionisation fraction, a Raman decay rate and the chi3-weighted density of several Kerr responses too. A table that never dips below zero is unchanged. A lifted one moves by at most 64 ulp of its largest value, 70 times below the error the default fit tolerance of 1e-12 allows on an interval of that scale; the tolerance is relative to each interval's own scale, so on an interval of much smaller values, near a vacuum, the lift can exceed it. A path that is negative, or changes sign, by more than rounding keeps the table it was fitted to, and the domain check still refuses a density or pre-ionisation fraction it reads that goes further below zero (the chi3-weighted Kerr density is not one it reads).
